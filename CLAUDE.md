## Что это за проект

Telegram-бот мониторинга фьючерсов Binance и Bybit.
Отслеживает ценовые импульсы по скользящему окну 24 часа и шлёт сигналы в Telegram.

**Деплой:** Railway (проект precious-tenderness, EU West Amsterdam)
**GitHub:** github.com/akcioner12/binance-impulse-bot
**Telegram-бот:** @Volume_Exchange_Bot

## Ключевые договорённости по логике

### Скользящее окно 24 часа
- НЕ фиксированные свечи — окно скользит непрерывно
- На каждой минутной свече сравниваем цену сейчас с ценой 24ч назад
- Движение может накапливаться постепенно — бот поймает как только сумма достигнет порога

### Сигналы
- Старт: 30% в любую сторону
- Шаг повторных: +10% (30->40->50->60...)
- Гистерезис сброса: 20 процентных пунктов от достигнутого уровня
  Пример: достигли 30% -> сброс только при откате ниже 10% (30-20=10)
  Без этого мелкие колебания ~0.1% вокруг порога вызывали спам сообщений

### Binance vs Bybit (без дублей)
- Если токен есть на Binance -> мониторится только через Binance
- Если токен есть только на Bybit -> мониторится через Bybit
- Каждый алерт содержит пометку биржи и прямую ссылку

### Схлопывание алертов
- Первый сигнал -> новое сообщение
- Следующие уровни -> редактирование того же сообщения (не спам)

## История критических багов

### 1. Binance WebSocket миграция (июнь 2026) — ИСПРАВЛЕНО
Симптом: бот подключался ("Подключено, 150 пар"), но не получал ни одного тика с Binance.
Причина: Binance перенёс kline-стримы под путь /market/. Старый URL устанавливал соединение, но данные не отправлял.
Исправление: BINANCE_FUTURES_WS = "wss://fstream.binance.com/market"

### 2. Спам сигналов при колебании цены у порога — ИСПРАВЛЕНО
Симптом: CLOUSDT прислал 5+ одинаковых "30% рост" при колебании 29.8%->31.1%.
Причина: сброс active-состояния при любом откате ниже 30%, даже на 0.1%.
Исправление: IMPULSE_RESET_HYSTERESIS=20.0 (сброс только при откате на 20п.п. ниже уровня)

### 3. WS не пересоздавался при обновлении списка пар — ИСПРАВЛЕНО
Симптом: SYNUSDT, DEXEUSDT, HEIUSDT — в списке были, сигналов не было.
Причина: symbols_refresher() обновлял список в памяти, но WS-соединения не пересоздавал.
Исправление: collectors_supervisor() — раз в 24ч останавливает все WS-задачи и создаёт новые.

### 4. Railway Variables переопределяли дефолты в коде — ИСПРАВЛЕНО
Симптом: /status показывал "Скользящее окно: 0ч".
Причина: при первом деплое выставлены WINDOW_MINUTES=30, SYMBOLS_REFRESH_SEC=3600 в Railway.
Исправление: обновлены переменные: WINDOW_MINUTES=1440, SYMBOLS_REFRESH_SEC=86400.

### 5. SQLite терял данные при редеплое — ИСПРАВЛЕНО
Причина: DB_PATH=bot_state.db — эфемерная файловая система контейнера.
Исправление: Railway Volume, DB_PATH=/data/bot_state.db.

## Диагностические логи

В main.py и analyzer.py добавлено:
- Счётчик тиков раз в час: "Диагностика: обработано тиков = N"
- Первый тик по символу: "Первый тик получен: XYZUSDT [Binance]"
- Приближение к порогу при abs_change >= 24%: DEBUG analyzer
- Полный список пар при старте: DEBUG main: Полный список Binance

Фильтры для Railway Logs:
- "[Binance]" — тики с Binance (если 0 — проблема с WS)
- "Первый тик" — проверка конкретного символа
- "Диагностика" — живость коллектора
- "TUSDT" — всё по конкретной паре
